# Baselines для токен-теггера рекламы

Цель: понять, что на самом деле выучила DeBERTa. Если простой метод близок к ней по качеству,
это главный вывод отчёта.

## Общие правила (одинаковые для всех моделей, включая DeBERTa)

1. **Одна токенная сетка.** Любой baseline выдаёт вероятность рекламы для своей единицы
   (позиция, абзац, предложение), эта вероятность раздаётся всем токенам DeBERTa внутри единицы
   (`label_tokens` из `src/adblock/tokenize.py`). Метки и метрики — те же, что у DeBERTa.
2. **Одни метрики:** `evaluate`, `auc_metrics`, `boundary_errors`, `char_metrics` из
   `src/adblock/metrics.py`; span-F1 при IoU 0.3 / 0.5 / 0.7.
3. **Общий декодер, без знания «блок ровно один».** Вероятности -> порог -> склейка кусков,
   разделённых маленьким промежутком -> удаление спанов короче `min_len` токенов.
   Декодер допускает 0, 1 или несколько блоков в тексте.
4. **Подбор только на val.** Порог, `min_len`, сглаживание, склейка и `C` логрегрессии —
   по span-F1@0.5 на val. Test считается один раз. TF-IDF-словарь и IDF обучаются только на train.
5. **OOD-проверка на `NaiAD_human`** тем же декодером и параметрами. Там 0–5 блоков в тексте:
   это проверяет, не опирается ли метод на структуру NaiAD_main.
6. В модели не подаются `ad_name`, `query`, `strategy`.

## Baselines

### 1. Position prior — «реклама там, где она обычно бывает»
- Относительная позиция токена `start_char / len(text)`, 50 корзин.
- Вероятность корзины = доля рекламных токенов в ней на train.
- Дальше общий декодер.
- Отвечает на вопрос: сколько качества даёт одна позиция, без чтения текста.

### 2. TF-IDF + LogReg по абзацам
- Документ = абзац (разбиение по `\n`, пустые строки пропускаются).
- Метка абзаца = 1, если больше половины его непробельных символов внутри рекламы.
- Признаки: TF-IDF слов и биграмм (`min_df=3`, `sublinear_tf=True`).
  Модель: LogReg с `class_weight="balanced"`, `C` из {0.5, 2, 8} по val.
- Отвечает на вопрос: хватает ли словаря рекламных фраз.
- Известное ограничение: в ~54% случаев реклама начинается внутри абзаца
  (её хвост), поэтому начало блока будет неточным — это видно по span-F1@0.7 и `boundary_errors`.

### 3. TF-IDF + LogReg по предложениям с соседями
- Документ = предложение (разбиение по `.!?…` + пробел и по `\n`; абзацы не склеиваются).
- Метка предложения — как у абзацев (большинство символов).
- Признаки: `[tfidf(предыдущее) | tfidf(текущее) | tfidf(следующее)]` — конкатенация, не сумма,
  чтобы модель различала «слово здесь» и «слово у соседа»; плюс два бинарных признака
  «первое в абзаце», «последнее в абзаце». Соседи берутся через границу абзаца;
  у крайних предложений сосед — нулевой вектор.
- Декодер: общий + сглаживание вероятностей по соседним предложениям (окно 1 или 3, по val).
- Отвечает на вопрос: хватает ли локального контекста из соседних предложений без трансформера.

## Что не делаем
- **Brand lookup:** в сплите бренды test не пересекаются с train, результат почти ноль по построению.
- **Позиция как признак в TF-IDF:** смешивает два сигнала, которые проверяют baselines 1 и 2–3 по отдельности.

## Как читать
- Position prior близок к DeBERTa -> модель в основном выучила позицию.
- TF-IDF (2 или 3) близок к DeBERTa -> задача решается словарём рекламных фраз.
- 3 заметно лучше 2 -> важна точная граница начала, а не только «есть ли реклама в абзаце».
- DeBERTa обгоняет всё и не теряет больше всех на human -> модель использует контекст и стиль.
